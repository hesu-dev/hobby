# 내보내기 및 CoC 가져오기 회귀 수정 설계

## 목표와 제약

이번 수정은 릴리스 전 검토에서 재현된 세 회귀만 해결한다. 첫째, desc 메시지는 DOM 전처리 단계에서 이미 앵커별 줄바꿈이 보존된 `text`를 만들지만 공용 스냅샷 빌더가 원본 `html`을 다시 직렬화하면서 줄바꿈을 제거한다. 둘째, CoC 아바타 별칭은 `??`로 후보 하나를 고른 뒤 검증해 빈 문자열이나 잘못된 상위 후보가 뒤의 유효 URL을 차단한다. 셋째, 아바타만 적용한 성공 응답이 실제 대상과 아바타 상태를 요약하지 않아 팝업에 잘못된 이름과 `Attributes 0/0, Abilities 0/0`만 표시된다. 기존 Chrome 무탭 ZIP은 재빌드하면 소스의 3탭 상태로 덮이므로 이 작업에서 릴리스 빌드를 실행하지 않고 읽기 전용 무결성 검증만 수행한다. 원래 작업 트리의 미추적 접근성 계획 문서도 수정하거나 커밋하지 않는다.

## 선택한 접근

desc 처리에는 두 대안이 있다. 공용 HTML 직렬화기가 블록 요소와 desc 앵커를 모두 이해하게 만들 수 있지만, 일반 메시지의 인라인 강조 보존 범위까지 넓어져 회귀 면적이 크다. 대신 `hasDescStyle`인 메시지는 이미 플랫폼별 DOM 수집기가 만든 줄바꿈 보존 `text`를 우선하고, 일반 메시지만 HTML 직렬화를 사용한다. 이는 기존 데이터 흐름의 책임 경계를 유지하는 최소 수정이다.

아바타 URL은 지원 별칭을 우선순위 배열로 만들고 각 후보를 개별 정규화한 뒤 첫 유효 URL을 선택한다. 적용 요약은 payload의 요청 여부와 page importer의 실제 `avatar.applied/failed` 결과를 명시적으로 전달한다. 성공 대상 이름은 page importer가 반환한 실제 캐릭터 이름을 우선하고 payload 이름은 fallback으로만 사용한다. 팝업은 기존 Attributes/Abilities 문구를 보존하면서 아바타 요청이 있을 때 `Avatar 1/1` 또는 `Avatar 0/1`을 추가한다.

## 오류 처리와 검증

유효한 별칭이 하나도 없고 attributes/abilities도 없으면 기존 오류를 유지한다. 아바타 저장 실패는 page importer의 `failed` 배열을 유지하고 요약에서는 적용 수를 0으로 보고한다. 테스트는 실제 공개 API와 포맷 함수를 사용한다. desc 테스트는 인접 앵커 HTML과 줄바꿈을 포함한 사전 처리 text를 공용 builder에 입력한다. CoC 테스트는 빈 값, 잘못된 URL, 중첩 별칭 fallback을 각각 확인하고, avatar-only 성공에서 실제 캐릭터 이름과 `Avatar 1/1` UI 문구를 검증한다. 각 테스트는 구현 전에 기대한 이유로 실패하는 것을 확인한 후 최소 코드를 적용한다. 마지막에는 전체 226개 이상 테스트, `git diff --check`, 네 릴리스 ZIP 무결성, Chrome ZIP의 live tab 0개를 다시 검증하고 독립 코드 리뷰에서 Critical/Important가 없어야 푸시한다.
